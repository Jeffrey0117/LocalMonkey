## 1. ⛔ 先修 bug：`<base href>` 讓所有路徑改寫失效

### 症狀

代理 `https://templatemo.com/` → HTML 回來了、CSS/JS/圖片的路徑也**正確改寫**成 `/p/templatemo-com/...`，但瀏覽器畫出來**完全沒有樣式**，所有資源載入失敗。

### 根因（2026-11-17 實測）

原站 `<head>` 裡有：

```html
<base href="https://templatemo.com/" />
```

我們原樣放行了它。於是瀏覽器把改寫後的相對路徑拿去**跟 base 解析**，而不是跟代理的 origin：

```
我們改寫出     /p/templatemo-com/tm-style-2026-ap29.css
瀏覽器實際請求  https://templatemo.com/p/templatemo-com/tm-style-2026-ap29.css   ← 404
```

`performance.getEntriesByType('resource')` 可以看到每一筆的 `transferSize: 0`、`decodedBodySize: 0`，網址前綴是原站而不是代理。注入的腳本也因此載不到（`window.__LM_OBSERVING__` 是 `false`，但 `<script>` tag 在 DOM 裡）——**tag 在不代表它載得到**。

chestnutzoe 沒有 `<base>`，所以同一套程式碼在那邊完全正常。這就是為什麼之前沒被發現。

### 修法

在 `src/lib/html.js` 的 HTML 改寫加一條：處理 `<base href="...">`（大小寫不拘、單雙引號都要吃、`/>` 與 `>` 都要吃）。

| base 指向 | 做什麼 |
|---|---|
| 該站的 `target_origin`（含只差尾斜線） | 改寫成 `/p/<siteId>/` |
| 其他網域 | **原樣保留**（那是真的跨網域意圖，不要亂動） |
| 相對路徑（`<base href="/foo/">`） | 改寫成 `/p/<siteId>/foo/` |
| 沒有 `<base>` | 什麼都不做（現狀） |

順序很重要：**`<base>` 的改寫要在根絕對路徑改寫之前或同一輪完成**，不要讓改寫後的結果又被 base 規則掃一次。

### 測試（必做）

- `<base href="https://www.example.com/">` + target 是同一個 origin → 變成 `/p/demo/`
- `<base href='https://www.example.com'>`（單引號、無尾斜線）→ 同上
- `<BASE HREF="...">`（大寫）→ 同上
- `<base href="https://other.test/">` → **原樣不動**
- `<base href="/sub/">` → `/p/demo/sub/`
- 沒有 base 的 HTML → 輸出與現在完全相同（回歸保護）
- **整合測試**：假上游回一份「帶 base + 根絕對路徑資源」的 HTML，斷言改寫後 base 指向代理、資源路徑也對
- **退化驗證**：把這條改寫拿掉，上面那些測試要真的變紅

### 順帶檢查同一類的東西

`<meta http-equiv="refresh" content="0; url=https://原站/...">` 也會把人踢出代理。查一下有沒有處理，沒有就一併做（指向 target_origin 的改寫成代理路徑，其他保留），並補測試。

## 2. 後台列表改成 Tampermonkey 儀表板

使用者給了 Tampermonkey v5.5.1「已安裝的使用者腳本」的截圖，要求「希望接近 Tampermonkey 本身」。

### 現在 vs 目標

現在是「左邊清單 + 右邊編輯器」常駐並排。目標是**先看到一張表**，要改某支才進編輯器。

```
┌────────────────────────────────────────────────────────────────────────┐
│ 🐒 LocalMonkey                                          v2  [+ 丟腳本] │  ← 深綠色 header
├────────────────────────────────────────────────────────────────────────┤
│  [已安裝的腳本]  [網站]  [設定]                                          │  ← 分頁
├───┬──────┬──────────────────┬──────┬───────┬────────┬──────┬──────┬────┤
│ # │ 已啟用│ 名稱           ▲ │ 版本 │ 大小  │ 站點    │ 功能 │最後更新│動作│
├───┼──────┼──────────────────┼──────┼───────┼────────┼──────┼──────┼────┤
│ 1 │ ●──  │ chestnutzoe 注入 │1.0.2 │ 1.2 KB│ 🖼      │ 🔗   │ 2 分鐘│✏️ 🗑│
│ 2 │ ──○  │ templatemo 注入  │1.0.0 │ 0.9 KB│ 🖼      │ 🔗   │ 1 小時│✏️ 🗑│
└───┴──────┴──────────────────┴──────┴───────┴────────┴──────┴──────┴────┘
```

### 欄位定義

| 欄 | 內容 | 備註 |
|---|---|---|
| `#` | `order_index`（1 起算） | 可直接編輯數字調順序 |
| 已啟用 | 開關 | 切換即時存檔。**停用的整列轉灰**（Tampermonkey 就是這樣） |
| 名稱 | `name` | **可排序**，預設依此排。點名稱本身＝進編輯器 |
| 版本 | `version`，沒有就 `—` | 可排序 |
| 大小 | `source` 的 byte 數，格式化成 KB | 可排序 |
| 站點 | 綁定站台的 favicon，最多 5 個 + `+N` | 見下方 §2.1 |
| 功能 | 小圖示：有 `@require` / 有 `@grant` / 有未支援的 `@grant`（紅） / 有投遞網址 | hover 顯示文字說明 |
| 最後更新 | `updated_at` 的相對時間（`2 分鐘`、`3 小時`、`9 天`） | 可排序。`title` 放絕對時間 |
| 動作 | ✏️ 編輯、🗑 刪除 | 刪除要二次確認 |

- 表頭點一下排序、再點一下反向，游標要是 pointer，目前排序欄顯示 ▲/▼
- 沒有任何腳本時顯示空狀態（置中，不是浮在角落——v2 踩過這個）
- 「功能」欄有未支援的 `@grant` 時標紅，hover 說明哪一個不支援

### 2.1 站點 favicon

伺服器端抓 `https://<host>/favicon.ico`（抓不到就試 `/apple-touch-icon.png`），**走現有的 SSRF 防護與大小上限**，存進既有的 `assets` 表（內容定址），投遞路徑 `/__lm/favicon/<siteId>`。

- **不要**用 `google.com/s2/favicons` 之類的第三方服務——那等於把使用者代理了哪些網站洩漏出去
- 抓不到就回一個內建的佔位 SVG（不要破圖、不要 404 噴到 console）
- 快取，不要每次開列表都重抓

### 2.2 編輯器變成第二層

點 ✏️ 或名稱 → 進入編輯畫面（**v2 已經做好的那個**：唯讀資訊列 + CodeMirror + 安裝網址列 + 版本提示）。左上角要有「← 返回清單」。

編輯畫面本身不要重做，只是改成從列表進入、而不是常駐並排。`Ctrl+S` 存檔行為維持。

### 2.3 外觀

- Header 用 Tampermonkey 的深綠色系，其餘維持現有深色主題（**不要**整個翻成淺色——使用者沒說要換主題，只說要「接近」那個儀表板的樣子）
- 表格要密、行高小、等寬字體用在版本/大小
- 窄螢幕：站點與功能欄可以收起來

### 2.4 「設定」分頁

新增一個唯讀的設定分頁，顯示目前生效的設定（port、`LOCALMONKEY_GM_ALLOW_HOSTS`、`ALLOW_PRIVATE`、資料庫路徑、保留的 token 檔位置）。**不要**做成可編輯——那些是 env，改了要重啟，做成輸入框會給人錯誤期待。每一項附上對應的環境變數名稱。
