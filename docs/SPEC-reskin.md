# LocalMonkey v7 — 重繪（Re-skin）

> 2026-11-19。前面五份仍有效：`SPEC.md`(v1 代理) / `SPEC-console.md`(v2 控制台) / `SPEC-dashboard.md`(v3 儀表板) / `SPEC-translate.md`(v4 翻譯) / `SPEC-rules.md`(v5/v6 規則)。
> 這份加的是**第三種模式**：不改上游的版面，而是把上游當資料來源，用我們自己的版型重畫。

---

## 0. 為什麼需要第三種模式

使用者要把代理的 templatemo 變成「蝦皮風格的模板商城」。

**規則層做不到。** templatemo 是 2008 年的表格式版面；蝦皮是卡片網格 + 價格標 + 店家列 + 黏底購買列。中間沒有 CSS 可以跨過去 —— 不是難，是那些元素在上游 DOM 裡根本不存在。再怎麼藏、怎麼挪，骨架還是人家的。

使用者的原話點出了正解：「**套別的站的皮　然後資料接近去**」。

```
現在（v1~v6）   上游 HTML → 改一改 → 送出          上游 = 頁面來源
這一份（v7）    上游 HTML → 抽資料 → 我們的版型渲染   上游 = 資料來源
```

### 這也順便修掉一個做歪的東西

v6 我用 `position: fixed` 的浮動面板做「右側購買區」，使用者的評語是「你怎麼另外加開一個鬼浮動面板」。他是對的 —— 那是貼在頁面上，不是做進版面裡。

重繪之後那塊是**我們版型的一部分**，問題自然消失。舊的那支 `templatee 會員下載面板` userscript 在重繪模式生效後要停用。

### 框法（影響設計取捨）

使用者在做的是**自己的模板商城原型**，templatemo 只是「真實感的假資料」。所以：

- 版型與商城機制是資產，之後把資料來源換成他自己的模板庫就能上線
- 抽取規則是**可拋棄**的那一層 —— 它綁死在 templatemo 的 DOM 上，本來就會換

**所以抽取與版型必須徹底分開。** 版型只認我們的資料模型，完全不知道 templatemo 存在。

## 1. 三層，界線要清楚

```
┌ 抽取層 ──────────────────────────────┐
│ 上游 HTML + 宣告式選擇器設定 → 正規化資料  │   ← 綁上游，會換
└──────────────────┬───────────────────┘
                   ▼  我們的資料模型（product / listing）
┌ 版型層 ──────────────────────────────┐
│ 資料 → 蝦皮風格 HTML                    │   ← 資產，不知道上游是誰
└──────────────────┬───────────────────┘
                   ▼
            送出（照舊走翻譯與規則層）
```

**版型層不准出現任何 templatemo 的字樣或選擇器。** 這條是這份規格最重要的紀律，違反了整個價值就沒了。

## 2. 資料模型

```js
// 列表頁
{ kind: 'listing', page: 1, totalPages: 39,
  items: [ /* product 的子集：id, name, image, tags, stats */ ] }

// 商品頁
{ kind: 'product',
  id: '628',
  name: '光環八號',
  nameOriginal: 'Lumen Eighty',
  image: '/images/...jpg',          // 相對上游，投遞時走代理
  gallery: ['...'],                  // 沒有就用 image 補
  description: '…',
  tags: ['multi-page', 'portfolio'],
  stats: { views: 11222, downloads: 1350, addedAt: '2026-07-15' },
  links: { preview: '/live/...', download: '/download/...' } }
```

缺欄位不是錯誤：缺 `gallery` 就用 `image`，缺 `stats` 就不顯示那一列。**任何一個欄位抽不到都不准讓頁面壞掉。**

## 3. 抽取層

### 3.1 設定長相（存 DB，可在控制台編輯）

```js
{
  match: '^/page/\\d+$',            // 路徑正則 → 這是哪種頁面
  kind: 'listing',
  item: '.thumbnail_270',            // 每一項的容器
  fields: {
    name:  { sel: 'h3 a, a', attr: 'text' },
    url:   { sel: 'a',       attr: 'href' },
    image: { sel: 'img',     attr: 'src'  },
    desc:  { sel: '.tn_desc', attr: 'text' },
  }
}
```

- `attr` 支援 `text` 與任意屬性名
- 多個 `match` 設定按順序比對，第一個中的勝出
- **沒有任何設定命中 → 退回現有的代理模式**（about、contact 這類頁面照舊）

### 3.2 ⛔ 伺服器端沒有 DOM，選擇器怎麼辦

這是本份規格的核心技術問題。

v5 的 `text-rewrite` 的 `scope` 與 v6 的 `no-translate` 已經各自處理過一次「伺服器端用選擇器」。**先去看那兩套怎麼做的，沿用同一套機制**，不要再發明第三套。

如果既有機制只支援簡單選擇器（單一 class / tag），那就：
- 在設定 UI 明確寫出支援到什麼程度
- 抽取失敗時**大聲失敗**（log + 控制台顯示），不要靜默退回代理模式讓人以為沒設好

如果評估後覺得既有機制撐不住這個用途（要取屬性、要取巢狀），**可以引入一個小型 HTML parser**。這是本專案第一次有正當理由破例：
- 只在**重繪模式**用，不碰既有的代理/翻譯/規則路徑
- 挑零依賴或極小的實作，並在 CLAUDE.md 寫明為什麼破例
- 在回報裡說明你的選擇與理由

### 3.3 快取

抽出來的資料存 DB（key = 上游路徑 + 上游 HTML 的 sha256）。上游沒變就不重抽。

## 4. 版型層：蝦皮風格

**抓版面骨架與間距，不要抄 logo、商標、配色商標性的部分。** 橘色主色（`#ee4d2d` 那個色系）是通用的電商橘，可以用。

### 4.1 列表頁

- 頂部：搜尋列（可用就接上游搜尋，不行就先擺著不作用並標示）、分類列（用標籤）
- 卡片網格（RWD：手機 2 欄、平板 3 欄、桌機 5~6 欄）
- 卡片內容：縮圖（1:1，`object-fit: cover`）、品名兩行截斷、**價格**、已售出（= 下載數）、標籤膠囊
- 分頁沿用上游的頁碼

### 4.2 商品頁

- 左：主圖 + 縮圖列（沒有多圖就只有主圖）
- 右：品名、價格區塊、規格選擇（= 授權方案）、**加入購物車 / 立即購買**、店家資訊
- 下：商品描述（上游的描述）、規格表（標籤、新增日期、觀看數、下載數）
- **購買面板是版型的一部分，不是浮動層**

### 4.3 價格與商城機制

上游沒有價格，**我們自己定**，存在 per-site 設定：

```
免費版   NT$0     預覽 + 下載
個人授權 NT$199   商業用途
企業授權 NT$699   多人、可轉授權
```

購物車與會員狀態存 `localStorage`（純前端示範，**不接金流**）。
下載閘門：非會員點下載 → 開方案面板（取代 v6 那支 userscript 的行為）。

### 4.4 資產

縮圖等資源**照舊走代理**（`/p/<site>/…`），不要直接連上游 —— 那會洩漏使用者的瀏覽，也會失去資源覆寫的能力。

## 5. 與既有各層的關係

| 層 | 重繪模式下 |
|---|---|
| 翻譯 | **照舊跑**。抽出來的文字（品名、描述）走同一套翻譯快取 |
| 規則（hide / css / text-*） | **對重繪後的 HTML 生效**（它是我們產生的，選擇器是我們自己的 class） |
| `no-translate` | 照舊 |
| 資源覆寫 | 照舊（logo、縮圖都能換） |
| userscript 注入 | 照舊。但 v6 那支 `templatee 會員下載面板` 要停用，功能已經被版型吸收 |

執行順序：**抽取 → 渲染 → 翻譯 → 規則 → 送出**。

## 6. 控制台

網站分頁新增「重繪」區塊：

- 開關（預設關）
- 抽取設定編輯（JSON 或表單，**要有「試一下」按鈕**顯示抽到幾項、每個欄位抽到什麼 —— 寫抽取規則最怕的是「寫了沒反應」）
- 版型選擇（目前只有 `shopee`，但要做成可選的）
- 價格方案設定

## 7. 硬性要求（使用者要快，只有這幾條）

1. **既有 1345 條測試全綠**（可以不寫新測試，但不准弄紅舊的）
2. **抽取失敗要退回代理模式，不准讓頁面壞掉或 500**
3. **版型層不准出現 templatemo 字樣或上游選擇器**（這條違反了整份規格就白做）
4. **真的用瀏覽器驗收並截圖**：列表頁、商品頁，RWD 至少看一個窄寬度
5. 不用 TDD、不用退化驗證、不用覆蓋率門檻
